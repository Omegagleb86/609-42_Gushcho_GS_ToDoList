# Тесты ToDoList на MSTest

Все проверки находятся в одном проекте и запускаются одной командой:

```bash
dotnet test ToDoList.Tests/ToDoList.Tests.csproj
```

Всего 96 проверок с учётом вариантов DataRow. Каждый тест проверяет одно поведение. Подготовка данных (Arrange) отделена от
вызова проверяемого действия (Act) и проверки результата (Assert).
Несколько Assert допустимы, если они подтверждают одно поведение — например,
отказ записи при ошибке или целостность удалённой ветки.

- `Core` — правила валидации и работа TodoService с заглушкой репозитория.
- `ViewModels` — создание, переименование, статусы, удаление, выбор категорий,
  CanExecute, параметры команд и уведомления. ITodoService подменяется заглушкой.
  Разные виды команд и входных данных — отдельные случаи DataRow.
- `Data` — настоящая SQLite через Entity Framework Core. Отдельные тесты на
  добавление, чтение каждого свойства, порядок, обновление названия/статуса/категории,
  перенос подзадачи, удаление, валидацию и сохранение в файл.

Тесты Data сохранены в общем проекте. По технической классификации это проверки
интеграции ORM с SQLite, но они также следуют правилу «один тест — одно поведение».
Настоящая база нужна, чтобы проверять SQL-связи и файловое хранение.

У каждого теста свои экземпляры и данные. Проверки БД создают изолированную базу
в памяти; подготовка строк выполняется через EF напрямую, без вызова методов
репозитория, которые проверяет тест. Тест файла создаёт уникальный временный
каталог и удаляет его после завершения. Рабочая база приложения не используется.

Запуск группы:

```bash
dotnet test ToDoList.Tests/ToDoList.Tests.csproj --filter TestCategory=Core
dotnet test ToDoList.Tests/ToDoList.Tests.csproj --filter TestCategory=ViewModels
dotnet test ToDoList.Tests/ToDoList.Tests.csproj --filter TestCategory=Data
```

Отдельный проект интеграционных тестов больше не нужен. ViewModel подключаются
исходниками через Compile/Link: для тестов не требуется запуск MAUI.
