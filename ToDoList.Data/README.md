# MySQL и разделение слоёв

```text
ToDoList (MAUI: Views, ViewModels)
  ├── ToDoList.Core → ToDoList.Models
  └── ToDoList.Data → ToDoList.Core → ToDoList.Models
```

- **Models** — ваш отдельный репозиторий, подключённый через ProjectReference.
  Его файлы не изменялись. Здесь остаются независимые контракты Category, TodoTask,
  TodoState, без ссылок на MAUI, EF Core и MySQL.
- **Core** — TodoRules (проверка названий, уникальности категорий, корректности дерева),
  TodoService и интерфейс ITodoRepository. Можно тестировать без UI и сервера БД.
- **Data** — EF-сущности, TodoDbContext, EfTodoRepository, фабрика MySQL и временный
  InMemoryTodoRepository. ORM-сущности отделены от Models, чтобы не добавлять
  требования EF к публичным моделям.
- **ViewModels** — состояние экрана и команды интерфейса; обращаются к TodoService.
  Только MauiProgram выбирает реализацию репозитория.

## Подключение MySQL

Нужен запущенный MySQL 8.0 или новее. Пакеты: EF Core 9 / Pomelo 9
(совместим с .NET 8+, включая используемый .NET 10), MySqlConnector 2.6.1.
Таблица совместимости: https://github.com/PomeloFoundation/Pomelo.EntityFrameworkCore.MySql#compatibility

В окружении **процесса приложения** установите переменную
`TODOLIST_MYSQL_CONNECTION`. Формат (значения нужно заменить своими):

```text
Server=127.0.0.1;Port=3306;Database=todolist;User ID=todolist_app;Password=<ваш пароль>;
```

Если запускаете через IDE, добавьте переменную в локальную конфигурацию запуска
и перезапустите приложение. Не добавляйте реальный пароль в отслеживаемые файлы
или launchSettings.json. Наличие переменной в терминале само по себе не означает,
что уже запущенная IDE или приложение получили её.

Для локального MAUI-приложения также можно передать строку из локального хранилища
настроек в `MySqlTodoRepositoryFactory.Create(...)`. Сейчас настройки выбираются
в `ToDoList/MauiProgram.cs`. На устройстве localhost означает само устройство;
используйте доступный устройству адрес сервера.

При первом LoadAsync вызывается EF `EnsureCreatedAsync`: создаётся новая БД
и таблицы, если их ещё нет и пользователь MySQL имеет соответствующие права.
Если БД создаёт администратор, достаточно заранее создать **пустую** отдельную
базу и разрешить приложению создание таблиц в ней. Существующие базы с другими
таблицами не подходят для автоматической инициализации.

Это начальная схема через EnsureCreated, **не миграции**. Она не обновляет уже
существующие таблицы при изменении модели. Перед изменениями схемы следует
ввести EF-миграции и отдельную процедуру их применения; не смешивать Migrate
с базой, созданной через EnsureCreated, без подготовки baseline-миграции.

При отсутствии строки подключения используется память и на экране показывается
это ограничение. При ошибке MySQL автоматического переключения в память нет:
показывается ошибка и доступен повтор операции.

Пароль не нужен для компиляции и обычных проверок. Подключение к реальному
серверу не проверялось: параметры пользователя ещё не заданы.

## Поведение и границы

- Сохраняется полный снимок **одного списка задач** в отдельной базе.
  Пользователей и совместного редактирования с нескольких устройств пока нет.
  Два независимых приложения с одной базой могут перезаписать изменения друг друга.
- Категории и задачи сохраняют Guid и порядок. Category.None не пишется в БД.
- ParentId — необязательная ссылка на задачу; CategoryId — необязательная
  ссылка на категорию. Глубина дерева не ограничивается числом уровней в коде.
- Сохранение и удаление выполняются в транзакции. При сбое старое состояние
  базы остаётся целым. Связи временно обнуляются **внутри** транзакции, затем
  восстанавливаются, что позволяет переносить и удалять ветки без нарушения FK.
- Название сохраняется по Enter или потере фокуса, категория и статус — сразу.
  Названия: 1–255 символов после удаления пробелов по краям.
- Статус родителя и потомков независим. Удаление родителя удаляет ветку.
- Для распространения приложения можно заменить прямое подключение к БД на
  API, оставив Models и Core независимыми от сервера.

## Проверки

Из корня рабочей папки:

```bash
dotnet test ToDoList.Tests/ToDoList.Tests.csproj
dotnet build ToDoList/ToDoList.csproj -f net10.0-maccatalyst -t:Compile
```

Тесты используют отдельную SQLite-базу в памяти: проверяют реальные связи,
обновление, удаление, вложенность и откат транзакции при искусственной ошибке.
Также проверяется генерация MySQL-схемы без подключения к серверу.
SQLite используется только в тестах; рабочая реализация настроена на MySQL.
